Quick-start guide: run an AS2 mission on AERPAW

Three phases. Each builds on the previous. Total time: ~20 min first run.

Phase 1 — plan your mission AS2 GUI
Your laptop · browser only
1
Open the AS2 web GUI
Navigate to your AS2 web interface. Draw waypoints on the map. Set altitude (min 25 m for AERPAW) and speed per waypoint.
2
Add your drones
Name each drone namespace: drone0, drone1, drone2. Match the count to your AERPAW vehicle allocation.
3
Download the mission file
Export as JSON. You get one file per drone, or a combined multi-UAV mission file. Save to your local machine.
drone0_mission.json drone1_mission.json drone2_mission.json
Phase 2 — set up AERPAW AERPAW console + E-VM
VPN → SSH → E-VM terminal
1
Create the experiment on console.aerpaw.org
Add N portable nodes (drones) + any fixed radio nodes. Schedule your time slot. Start the experiment — AERPAW brings up the E-VMs.
2
Connect via VPN + SSH into the E-VM
ssh -i ~/.ssh/aerpaw_key user@<evm-ip>
3
Copy your mission files to the E-VM
scp drone*_mission.json user@<evm-ip>:~/missions/
4
Launch the AERPAW platform bridge
One launch per drone. Replace the conn addresses with the MAVLink endpoints AERPAW assigned to your vehicles.
ros2 launch as2_platform_aerpaw aerpaw_platform.launch.py \ drone_id:=drone0 \ conn:=udpin://10.14.X.X:14550 \ use_aerpaw:=true ros2 launch as2_platform_aerpaw aerpaw_platform.launch.py \ drone_id:=drone1 \ conn:=udpin://10.14.X.Y:14550 \ use_aerpaw:=true
For the Digital Twin / SITL, use use_aerpaw:=false and conn:=udpin://127.0.0.1:14550
5
Verify connection — check all drones are alive
ros2 topic echo /drone0/self_localization/pose ros2 topic echo /drone1/self_localization/pose
You should see GPS position updating at ~20 Hz. If not, check your MAVLink conn string.
Phase 3 — run and watch E-VM + QGroundControl
Run mission · watch in QGC
1
Open QGroundControl on your laptop
Connect to the AERPAW MAVLink stream over VPN. You'll see all drones on the NC State map — live position, altitude, battery.
QGC is read-only here. It monitors; AS2 commands.
2
Run the mission
Back on the E-VM terminal, launch the experiment. All drones arm, take off, and execute your planned mission simultaneously.
ros2 launch as2_experiment_aerpaw_multiuav \ aerpaw_digital_twin.launch.py \ conn_drone0:=udpin://10.14.X.X:14550 \ conn_drone1:=udpin://10.14.X.Y:14550 \ use_aerpaw:=true python3 missions/your_mission.py
3
Watch in QGroundControl
Drones move on the map exactly as planned. If anything looks wrong, the safety pilot can take over in QGC at any time.
4
Stop and clean up
Ctrl+C (in mission terminal) ros2 lifecycle set /drone0/platform shutdown ros2 lifecycle set /drone1/platform shutdown
Then stop the experiment from the OEO console to release AERPAW resources.

First time? Run on the Digital Twin first

Use use_aerpaw:=false and local SITL connections. Identical workflow — no hardware risk.
